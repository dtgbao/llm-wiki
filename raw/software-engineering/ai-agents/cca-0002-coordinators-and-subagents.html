Hub-and-spoke

                ┌──────────── Coordinator ─────────────┐
                │ decompose · select · route · merge    │
                └──┬─────────┬──────────┬─────────┬────┘
           prompt ↓↑ result  ↓↑         ↓↑        ↓↑
              ┌────────┐ ┌────────┐ ┌──────────┐ ┌────────┐
              │ Search │ │Analyze │ │Synthesize│ │ Report │
              └────────┘ └────────┘ └──────────┘ └────────┘
                 no arrows between subagents: all traffic goes through the hub

Route all communication through the coordinator. You get one place for observability, consistent error handling and controlled information flow (exam guide 1.2).

The coordinator's four jobs

JobGoodFailure the exam shows you
DecomposeSubtopics cover the whole topic, with no overlapToo narrow: "creative industries" → only visual arts
SelectPick subagents by query complexityAlways run the full pipeline, even for one fact
DelegateObjective, output format, tools and sources, boundariesVague brief → duplicate searches, gaps
RefineFind gaps → targeted queries → synthesize againPublish the first synthesis as-is

Anthropic's research system gives each subagent "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries." Without these, agents duplicate work and leave gaps. It also scales effort: one agent for a simple fact, many for complex research (Anthropic: multi-agent research system).

Root-cause rule. Every subagent succeeds, but the report misses whole areas? Read the coordinator's subtask list first. The subagents did their assigned work correctly. The assignment was wrong.

Give the coordinator goals and quality criteria, not step-by-step procedures. Goals let subagents adapt to what they find (exam guide 1.3).

Spawning subagents

ClaudeAgentOptions(
    allowed_tools=["Read", "Grep", "Agent"],   # exam guide: "Task". Without it: no subagents
    agents={
        "searcher": AgentDefinition(
            description="Web research specialist. Use for finding sources.",  # WHEN to use
            prompt="You find and cite primary sources...",                     # system prompt
            tools=["WebSearch", "WebFetch"],                                    # scoped tools
            model="sonnet",                                                     # optional
        )})

Name check. The exam guide calls the spawning tool Task. Current SDK docs call it Agent, and the init tool list still shows Task (Agent SDK: subagents). On the exam, read "Task tool" as this tool.

AgentDefinition requires a description (when to use the agent) and a prompt (its system prompt). tools restricts what it can do. If you omit tools, it inherits every tool.

Context passing: only the prompt goes across

A subagent starts fresh. It does not see the coordinator's conversation. "The only content you pass from parent to subagent is the Agent tool's prompt string" (SDK docs). Subagents do not share memory between calls.

# BAD: the synthesis subagent cannot see "above"
"Summarize the results above into a report."

# GOOD: complete findings, content kept apart from metadata
"Write a cited report on remote work and cities.
 Findings:
 [{"claim": "...", "excerpt": "...", "url": "...", "doc": "...", "page": 4}, ...]"

Structured records keep source attribution through each handoff (exam guide 1.3). Lesson 16 builds on this.

Exception: a fork copies the conversation so far, instead of starting fresh. Use a fork to try different approaches from one shared baseline.

Parallel: one response, many calls

Coordinator response (ONE turn):        NOT this (three turns):
  tool_use Agent → searcher: "housing"     turn 1: Agent → searcher
  tool_use Agent → searcher: "transit"     turn 2: Agent → searcher
  tool_use Agent → searcher: "retail"      turn 3: Agent → searcher

Parallel subagents finish in the time of the slowest one, not the sum (SDK docs). Anthropic's lead agent runs 3–5 subagents in parallel. With parallel tool calls also inside the subagents, research time fell by up to 90% (research system).
